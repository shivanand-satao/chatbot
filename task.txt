## 6. Intelligent Question Routing

Implement a dedicated intent router that determines whether a question requires dataset analytics, document retrieval, both, clarification, or an unsupported response.

### A. Dataset-specific questions

Examples:

- Compare crime figures for 2012 and 2013.
- Which states reported the highest crime figures in 2020?
- Show the year-over-year change in a crime category.
- Compare Maharashtra and Karnataka.
- What does the serious_fraud dataset contain?

The workflow must be:

**Question → Dataset metadata vector search → Schema validation → Data availability checks → Dynamic SQL generation → SQL validation → PostgreSQL execution → LLM analysis → Answer.**

Use pgvector to discover the relevant tables and columns, but verify their actual availability before generating SQL.

The final numerical answer must be based on real database query results, not on the metadata embeddings or the LLM's general knowledge.

### B. Document-based questions

Examples:

- What does the official report say about cybercrime?
- Explain a crime definition according to the uploaded book.
- Summarize the chapter about economic offences.

The workflow must be:

**Question → Document vector search → Retrieve original text chunks → LLM answer generation → Answer with citations.**

Use the document vector index for these questions. Cite the document title and page number wherever available.

Do not generate SQL unnecessarily for questions that can be answered directly from the documents.

### C. Hybrid questions

Examples:

- Compare the crime figures for 2012 and 2013 and explain the trend using the official report.
- Compare financial fraud figures and explain the relevant findings from the uploaded book.

The chatbot must retrieve dataset metadata, execute validated SQL, retrieve relevant document passages, and combine the evidence into one answer.

Clearly distinguish database-derived numerical findings from document-supported explanations.

If either source lacks sufficient information, explain the limitation instead of fabricating an answer.

### D. Ambiguous questions

Use conversation history to understand follow-up questions. If a required year, metric, dataset, or other detail remains ambiguous, ask the user for clarification when necessary.

## 7. Dynamic Natural-Language-to-SQL Engine

The chatbot must generate SQL dynamically rather than relying on hardcoded queries for every possible question.

After retrieving relevant dataset metadata, inspect the actual schema and validate the requested analysis.

Support:

- Filtering and sorting.
- Aggregations and grouping.
- Year-over-year comparisons.
- Percentage and absolute changes.
- State-wise and category-wise comparisons.
- Joins using verified relationships.
- Common table expressions and window functions when appropriate.

Understand the actual meaning and units of the metrics. Do not confuse crime counts, rates, percentages, and monetary losses.

Before executing any generated SQL:

- Restrict execution to approved analytical tables and columns.
- Use a least-privilege, read-only database role.
- Reject data-modifying and schema-modifying statements.
- Reject multiple statements and unsupported SQL constructs.
- Use parameterized queries for user-provided values.
- Validate identifiers against the actual schema.
- Enforce query timeouts and result limits.
- Prevent SQL injection and unauthorized access to internal application tables.
- Enforce existing user and administrator permissions.

Do not rely solely on the LLM prompt for security. If a query cannot be safely validated, do not execute it.
